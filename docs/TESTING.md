# Матрица проверок

Физическое устройство: Cudy WR3000S v1, OpenWrt 24.10.5
`r29087-d9c5716d1d`, mediatek/filogic, aarch64_cortex-a53.
Podkop v0.7.14-r1; sing-box 1.12.22-r1 с `with_clash_api`, `with_quic`, `with_utls`.

Проверено на этом устройстве:

- Подписка из 15 VLESS-узлов; разбор, проверка sing-box, HTTPS HEAD и повторные
  HTTPS GET с передачей 16 КиБ через каждый узел. Неудачные узлы не удаляются.
- Различающиеся результаты повторных попыток действительно встречались:
  транспортные тесты не считаются постоянным свойством сервера.
- Проверка будущей конфигурации на копии UCI, без изменения рабочего Podkop.
- URI fixtures VLESS/VMess/Trojan/SS/Hysteria2/TUIC: разбор и `sing-box check`.
- Детерминированное выполнение настоящего цикла монитора с fault injection:
  стартовый минимум, три последовательных ошибки, резерв, отсутствие возврата,
  отсутствие ложного счётчика при отказе API, cooldown и запрет автопереключения.
- Отказ при неизвестном URI-параметре и попытке получить локальный файл из JSON.
- Реальный selector в изолированном sing-box: искусственный отказ текущего
  outbound, наблюдение ошибок 1/2/3, переключение через API, восстановление
  узла без возврата и ручное переключение после повторных передач данных.
- Watchdog восстанавливает обе конфигурации в песочнице с безопасной заменой
  init-скрипта. Рабочий Podkop для проверки rollback не перезапускался.
- Установка IPK через opkg, загрузка RPC и страницы LuCI Services на роутере.
- Две подписки с одинаковыми узлами объединяются в 15 уникальных записей,
  все 15 сохраняются независимо от результата проверки.
- APK собран официальным OpenWrt SDK 25.12.0, запуск на APK-системе не проверялся.

Измеренная RSS оболочки монитора в изолированном тесте: 1364 КиБ;
временного тестового ядра sing-box с двумя узлами: 25036 КиБ. Это не оценка
полного пикового потребления с curl/jq и большим пулом. В обычном режиме
используется существующий процесс sing-box; второй нужен только для проверки
кандидатов и подписок. TUN/TPROXY в нём не создаются.

Рабочие `/etc/config/podkop` и `/etc/sing-box/config.json` контролируются SHA-256
до и после тестов. Тестовые ядра слушают только loopback и не имеют TUN/TPROXY.

Другие модели, архитектуры и версии OpenWrt не проходили аппаратные проверки.
Сборка APK через SDK не означает сетевую проверку на OpenWrt с APK.
Сценарии обновления Podkop, отключения питания и длительной непрерывной работы
требуют дальнейших испытаний; выпуск имеет статус preview.

Для повторения тестов:

```sh
python3 tests/make_fixtures.py
# Загрузить files/ и tests/ в отдельный /tmp/pas-lab, задать PAS_* как в router-suite.sh.
sh tests/router-suite.sh tests/fixtures
```

`tools/router.py` — транспорт для разработки. Требует Paramiko, пароль только
в переменной окружения и заранее сохранённый проверенный SSH host key.
Секретные конфигурации и исходные подписки в репозиторий не включаются.

## Регрессии 0.1.1

`tests/import-regression.sh` выполняет настоящий загрузчик и RPC с пустым
приватным каталогом, выключенным мониторингом и `auto_apply=1`: импорт проходит,
применение не вызывается. Проверяются ошибка скачивания с сохранением пула,
повторная загрузка, две подписки, запуск updater через RPC и регистрации procd.
Реальные изолированные проверки закрытых loopback-портов проверяют очередь
при включённом и выключенном мониторинге и отображение результата без удаления узлов.

`tests/installer-regression.sh` заменяет GitHub и операции установки fixtures:
первая установка, обновление старой версии, пропуск равной/новой версии,
`--check`, отказ при неверном SHA-256 и недоступности GitHub, игнорирование
черновиков и неполностью загруженных релизов. Сравнение IPK-версий выполняет
настоящий opkg. Это не аппаратная проверка установщика APK.

`tests/parallel-regression.sh` запускает реальное изолированное ядро и подменяет
только передачу тела с контролируемой длительностью: проверяется наблюдаемый
предел 1 и 3 одновременных запросов, выбор минимальной задержки, повтор после
первой неудачи и сохранение узла с четырьмя неудачами. Это тест планировщика,
а не измерение скорости сети. В LuCI проверены полная проверка 15 узлов и
добавление второй подписки через «Save & Apply» с автоматической перезагрузкой
updater через procd. Рабочий Podkop при этом не перезапускался.

## Регрессии 0.1.2

На том же устройстве две действующие подписки дали 29 уникальных серверов.
Параллельная проверка заняла 37 с, 14 узлов прошли передачу данных; все 29 остались
в пуле. Результат зависит от состояния сети и не является гарантией задержки.
Изолированный тест реального failover прошёл, включая ручной выбор. RSS оболочки
монитора 1448 КиБ, изолированного ядра с двумя узлами 21960 КиБ.

`recovery-regression.sh`: реальный монитор с управляемыми отказами сетевых функций.
Проверены остановка переключений при потере WAN, сброс счётчика и три свежие
ошибки после восстановления, потеря WAN во время поиска, исключение текущего
проблемного узла, откат кандидата после отказа реального маршрута и выбор следующего,
повторный поиск до восстановления, срочный запрос подписок, восстановление stale lock.

`dynamic-regression.sh`: настоящий importer/sync с HTTP fixtures и контрольной
границей применения. Автоматическое первое подключение, частично недоступный
провайдер с сохранением кэша, новые серверы другого провайдера, полный обрыв,
следующий автоматический цикл восстановления и сохранение явной паузы.

Прямая HTTPS-проверка с меткой обхода проверена реальным соединением. Физический
WAN для этих автоматических тестов не отключался. Нагрузка параллельного
планировщика: наблюдаемый максимум 1/3, время 20/7 с с одинаковыми тестовыми задержками.

`live-integration.sh`: реальная транзакция подключения с UCI, API и HTTPS через
изолированный sing-box; init-fixture управляет только собственным PID в /tmp.
Проверены первое подключение, добавление третьего узла с сохранением текущего,
отсутствие перезапуска при неизменном пуле и detach к исходному proxy.
После теста хеши рабочих Podkop UCI и sing-box config совпали с исходными.

`lan-panel-regression.sh`: настоящий CGI и ucode-проверка адресов с фикстурами
netifd. Анонимный доступ из LAN /23, IPv6 /64 и IPv4-mapped; отказ соседней сети,
WAN, внешнему клиенту, постороннему Host, cross-origin POST, неизвестной команде
и некорректному тегу. Проверены допустимые команды и атомарная очередь выбора.

На рабочем роутере автоматический пул подключён штатным Podkop. Пользователь
подтвердил, что отключил выбранный тестовый узел. Монитор самостоятельно выбрал
резерв и подтвердил HTTPS-передачу; это зафиксировано журналом основного сервиса.
Аварийный поиск в этом выпуске ждёт результаты параллельной проверки всего пула.
Это может занимать десятки секунд; по решению пользователя опубликован именно
проверенный работающий алгоритм, без последующих экспериментальных ускорений.

CGI дополнительно проверен реальным HTTP-запросом через установленный uhttpd
без cookies. uhttpd не экспортирует произвольный X-PAS-Panel в CGI: защита POST
использует передаваемые Origin, Host и application/json; источник проверяется
по текущим LAN-подсетям. Подходящий Origin достигает обработчика команд,
чужой или отсутствующий Origin отклоняется.

## Регрессии 0.1.3

`tests/reconcile-regression.sh` запускается в GitHub Actions под BusyBox ash.
UCI собирается из закреплённых исходников OpenWrt, sing-box 1.12.22 проверяет
кандидатные конфигурации. Используются только временные UCI, вымышленные узлы
example.com/org/net и фикстура перезапуска; доступ к пользовательским роутерам
не требуется. Сетевая квалификация подменена детерминированными ответами.

Проверяются первоначальное подключение, отсутствие лишних перезапусков,
ручная замена main на URL, удаление всех/части узлов, недостающие runtime
outbounds, сохранение пользовательских списков и чужих секций, обновление
снимка detach, конфликт владения, пользовательские правила в служебной секции,
WAN, несохранённые правки LuCI, гонка во время preflight, отсутствие кандидата,
rollback после неудачного запуска, отключённый режим и различение ошибок API.
