# Podkop AutoSwitch: архитектура

## Контракт

Один штатный процесс sing-box. Главная секция Podkop сохраняет своё имя и
правила, меняется только её outbound на selector. Каждый сервер представлен
служебной UCI-секцией `pas_<sha256>` (outbound `pas_<sha256>-out`) без списков маршрутизации. Никакие
исходные файлы Podkop, firewall, DHCP или DNS аддон не патчит.

Проверенные точки интеграции официального itdoginfo/podkop:
`get_outbound_tag_by_section`, `sing_box_cf_add_json_outbound`,
`sing_box_cm_add_raw_outbound`, тип секции `section`, режим `outbound`.
Источник main: da8bd40983aaab4d29614d38c8d6214d0a217e3e; отдельно сверены
установленные функции Podkop v0.7.14-r1 на Cudy WR3000S v1.

## Состояния

При первом подключении: проверка пула, выбор минимальной задержки. Перезапуск
монитора сохраняет текущий выбор. При отказе выполняется прямая HTTPS-проверка
WAN через временный direct outbound с проверенной меткой обхода Podkop.
Без подтверждённого прямого доступа переключения и изменения пула приостановлены.
Затем каждые 5 секунд проверяется текущий outbound через HTTPS GET локального
service proxy Podkop (опционально — облегчённый Clash delay API).
После 3 последовательных неудач выполняется новый поиск, включая повторную
проверку кандидата перед переключением. Здоровый текущий сервер сохраняется.
Восстановление прежнего сервера не вызывает возврата. Пауза между переключениями
по умолчанию 30 секунд. При недоступности управляющего API счётчик ошибок
сервера не увеличивается. Если нет рабочего резерва, выбор сохраняется.

Рабочее состояние и журнал результатов — в `/tmp`; на flash записывается
только изменение выбранного сервера или пула. Последний рабочий пул и исходная
конфигурация Podkop хранятся с правами 0600.

## Подписки и обновление

Процесс updater работает независимо от переключателя мониторинга. Сохранение
и применение UCI перезагружает службу через procd и запускает импорт. Установка
запускает загрузчик сразу; RPC умеет повторно запустить остановленную службу.
Монитор запускается только при `enabled=1`. Автоматическое применение пула
дополнительно проверяет этот флаг; выключенный мониторинг не меняет Podkop.
Статусы импорта и проверки, счётчики и безопасные коды ошибок доступны в LuCI.
URL и диагностические сообщения с возможными секретами через RPC не передаются.

HTTPS-загрузка с проверкой сертификата, предел размера/числа узлов/времени.
Поддерживаются sing-box JSON, массив outbound, URI-список и его base64-обёртка.
Нативный JSON сохраняет параметры самостоятельного outbound установленного
sing-box; конечный арбитр — `sing-box check`. Конфигурации маршрутизации,
inbounds, endpoints и внешние файлы из подписки не импортируются.
Clash YAML не является форматом sing-box и в этом выпуске не импортируется.

Обновление сначала формирует staged pool. Существующий рабочий узел сохраняется
в пуле, если исчез из подписки, пока он активен. Изменение пула сравнивается
по содержимому. При enabled=1 синхронизация автоматическая: отдельного шага
применения нет. Обновление состава требует штатного перезапуска; неизменный пул
его не вызывает. Загрузка имеет собственную блокировку и не останавливает
монитор. Проверки приложения, failover и ручной диагностики используют разные
локальные порты. Квалификация выполняется до блокировки мутации; перед записью
повторно проверяются WAN, выбранный узел и хеш исходной UCI. Изменения Podkop
другим администратором не перетираются. Кэш каждого источника позволяет обновить
часть подписок при отказе остальных. Пустые/невалидные обновления не заменяют пул.
После исчерпания резерва монитор запрашивает срочный импорт и повторяет поиск
через recovery_retry (10 с), updater ограничивает запросы outage_refresh (60 с). До записи UCI проверяется
будущая конфигурация sing-box. Во время применения работает отдельный watchdog,
возвращающий исходные UCI и конфигурацию при неподтверждённой транзакции.

## Ограничения проверок

HTTPS GET проверяет передачу тела ответа через конкретный proxy outbound, не ICMP.
Кандидаты проверяются временным ядром с loopback mixed inbounds, минимум две
успешные передачи подряд из четырёх попыток. В неосновном режиме HTTPS delay
выполняет HEAD; этот режим слабее и не проверяет тело ответа.
Это не доказательство работоспособности любого сайта, UDP, QUIC или потокового
видео. Для защиты от сбоя единственной контрольной точки предусмотрены несколько
URL: достаточно одного успешного, задержка — время первой успешной проверки.
Проверки выполняются ограниченным пулом фоновых процессов: по умолчанию 3,
настраивается от 1 до 8. Один временный sing-box обслуживает все процессы;
у каждого собственный loopback-порт и атомарный файл результата. Освободившееся
место сразу занимает следующий узел. Повторные передачи одного узла остаются
последовательными. Фонового опроса всего пула каждые 5 секунд нет. При поиске большого пула следующий цикл
откладывается; интервал не является гарантией realtime.

## Совместимость

Архитектурно независимые POSIX/BusyBox shell, jq и LuCI JavaScript. Поддержка
определяется проверкой возможностей на устройстве, а не только номером версии.
Пакеты IPK для opkg; APK собираются официальным SDK целевого выпуска OpenWrt.
Нельзя выдавать tar.gz за APK или объявлять все архитектуры проверенными.

## Восстановление после ручных изменений (0.1.3)

Хеш всего Podkop используется для обнаружения изменений и гонок во время
preflight, но не запрещает последующее применение. Кандидат строится из текущей
UCI. Отсутствующие ранее управляемые секции создаются заново; существующие
заменяются только по точному списку attachment и при наличии pas_managed=1.
Дополнительные пользовательские опции в такой секции считаются конфликтом.

Монитор запрашивает reconcile при изменении UCI, исчезновении selector или
служебного inbound. Updater ограничивает повторы outage_refresh; при старте
синхронизация выполняется сразу. Подготовка имеет отдельные UCI savedir,
поэтому промежуточные изменения не попадают в рабочую очередь LuCI.

Snapshot отключения строится из текущей UCI с удалением наших секций и
восстановлением только принадлежащих аддону полей целевого proxy и service
proxy. Ручной новый proxy становится новой основой отключения. Оба снимка
входят в rollback-транзакцию; старый watchdog-format остаётся совместимым.
Если managed UCI и runtime-пул уже совпадают, изменения правил принимаются
без перезапуска. Перед записью повторно проверяются хеш и pending UCI.
