# Podkop AutoSwitch

Аддон для [официального Podkop ITDog](https://github.com/itdoginfo/podkop) на OpenWrt.
Несколько подписок, проверка реального HTTPS-трафика, выбор рабочего сервера,
автопереключение после трёх ошибок и страница **Services → Podkop AutoSwitch**.

**0.1.3 — предварительный выпуск.** Совместимость проверяется на самом устройстве.
Нельзя считать любую версию OpenWrt, sing-box или любой формат подписки
поддержанными только потому, что пакет устанавливается.

## Установка и обновление

Сначала установите официальный Podkop и убедитесь, что он работает.
На OpenWrt используется `sh` (BusyBox ash); скрипт также совместим с bash.

```sh
curl -fLsS https://raw.githubusercontent.com/fackerghost/Podkop-AutoSwitch/main/install.sh -o /tmp/pas-install.sh && sh /tmp/pas-install.sh
```

Одна и та же команда подходит для **первой установки и обновления**. Скрипт
находит последний полностью опубликованный релиз (включая preview), определяет
opkg/APK, сравнивает версии, проверяет SHA-256 и устанавливает пакет. Если уже
установлена такая же или более новая версия, ничего не переустанавливается.
Подписки и настройки сохраняются. Обновляется только аддон и недостающие зависимости,
общего обновления пакетов OpenWrt нет. При первой установке автоматический режим
**включён**: достаточно добавить подписки и применить настройки. Сохранённая
пауза (`enabled=0`) при обновлении остаётся паузой; включите «Автоматический режим»,
если хотите возобновить управление. Старый флаг `auto_apply` больше не требуется.

Проверить наличие обновления без установки:

```sh
curl -fLsS https://raw.githubusercontent.com/fackerghost/Podkop-AutoSwitch/main/install.sh -o /tmp/pas-install.sh && sh /tmp/pas-install.sh --check
```

При необходимости конкретный выпуск выбирается через `PAS_VERSION=v0.1.3 sh /tmp/pas-install.sh`.
Понижение версии скрипт не выполняет. Старые команды с `/v0.1.0/install.sh`
закреплены за 0.1.0 — замените их командой с `/main/install.sh` выше.
Для APK применяется `--allow-untrusted` только к локальному пакету релиза;
контрольная сумма получена по HTTPS. Это не независимая подпись издателя.

Ручная установка IPK:

```sh
opkg update
opkg install /tmp/podkop-autoswitch_0.1.3-1_all.ipk
```

Откройте LuCI: **Services → Podkop AutoSwitch**. Если пункт не появился,
перезайдите в LuCI после `/etc/init.d/rpcd restart`.

## Быстрая панель

Откройте **http://192.168.1.1/autoswitch/**, заменив адрес на текущий адрес
вашего роутера. Ссылка `/autoswitch/` работает на любой LAN-подсети, по HTTP/HTTPS
и с нестандартным портом; в LuCI она строится из текущего адреса автоматически.

**Вход не требуется.** Панель показывает текущий сервер и задержки, позволяет
переключить сервер, обновить подписки и проверить пул. Доступ разрешён клиентам
текущих LAN-подсетей, определяемых через netifd и сети firewall-зоны `lan`
(по умолчанию интерфейс `lan`). Проверяются IPv4/IPv6, Host и источник POST.
Пользователи этой LAN получают перечисленные действия без пароля. Полные
настройки и изменение URL остаются в LuCI с обычной авторизацией.

## Первичная настройка

1. Добавьте одну или несколько HTTPS-подписок и выберите существующую proxy-секцию Podkop.
2. Нажмите **«Сохранить и применить»** внизу страницы. Подписки загрузятся
   автоматически, даже при выключенном мониторинге. Обычная кнопка «Сохранить»
   лишь откладывает изменения LuCI; их нужно применить.
3. Дождитесь «Загружено серверов: …». При ошибке причина и номер подписки
   показываются в состоянии. «Обновить подписки» повторяет загрузку сохранённых
   настроек; «Проверить все серверы» запускает отдельное тестовое ядро.
   Оба действия доступны при выключенном мониторинге. Проверка показывает прогресс
   и итог; неответившие серверы остаются в списке и проверяются заново.
   По умолчанию проверяются **3 сервера одновременно**. Настройка «Параллельных
   проверок» допускает 1–8; увеличение расходует больше памяти и полосы канала.
4. При включённом автоматическом режиме пул проверяется и подключается сам.
   Отдельной кнопки «Применить пул» нет. Первый запуск и изменение состава
   требуют штатного перезапуска Podkop; до записи создаётся резервная копия,
   проверяется конфигурация и запускается watchdog отката. Неизменившийся пул
   перезапуска не вызывает. Рабочий выбранный сервер сохраняется при обновлении.
5. После подключения доступны кнопки «Переключить». Результат ручного выбора
   тоже проверяется передачей данных; при отказе восстанавливается прежний выбор.

Если проверка передачи данных включена (по умолчанию), используется штатный
loopback service proxy Podkop. Поэтому также включается загрузка списков
Podkop через выбранную секцию. Уже настроенный service proxy другой секции
считается конфликтом; аддон откажется менять его без устранения конфликта.
Существующие правила доменов/подсетей и маршруты секции сохраняются.

Если вы вручную заменили прокси в `main` или удалили служебные секции `pas_*`,
включённый AutoSwitch автоматически восстановит свою группу и серверы из подписок.
Также это происходит при следующем включении автоматического режима. Пока режим
выключен, ручной прокси остаётся под вашим управлением. Для обычной смены сервера
используйте кнопки AutoSwitch — они переключают через API без перезапуска.

При восстановлении используются текущие настройки Podkop: доменные списки,
подсети и сторонние секции сохраняются. Восстановление группы требует одного
штатного перезапуска после проверки кандидатов; короткий разрыв возможен.
Повторные попытки ограничены интервалом восстановления подписок (по умолчанию 60 с).
При отсутствии прямого интернета или рабочего кандидата конфигурация не применяется.
Несохранённые правки LuCI, чужая секция с совпавшим именем или пользовательские
правила внутри служебной секции остаются конфликтом: правила следует хранить
в основной или собственной секции, а служебные секции используются только для узлов.

Снимок для последующего отключения аддона обновляется с сохранением новых правил
и последнего вручную заданного прокси. Сообщение «Группа серверов изменена в Podkop»
теперь отличается от настоящей ошибки связи с API sing-box.

## Как принимается решение

- При первом подключении аддон проверяет весь пул и выбирает минимальную измеренную
  задержку среди узлов, прошедших проверку передачи данных.
- Текущий сервер проверяется каждые 5 секунд. По умолчанию это HTTPS GET через
  штатный локальный proxy, с проверкой кода 200 и полученного тела, не ICMP.
  При неудаче основного URL используется запасной URL, чтобы сбой одной
  контрольной точки не считался отказом прокси.
- После трёх ошибок подряд выполняется поиск резерва. По умолчанию не чаще одного
  переключения за 30 секунд; повторный поиск после завершения неудачного — через
  10 секунд. При отсутствии резерва запрашиваются свежие подписки: не чаще раза
  в 60 секунд по умолчанию, до восстановления. Обычное обновление — раз в час.
  Старые сохранённые интервалы при обновлении пакета сохраняются.
- При отказе прокси проверяется прямой HTTPS-доступ в интернет с обходом Podkop.
  Если ни одна контрольная точка не отвечает, выбор сохраняется, счётчик ошибок
  прокси сбрасывается. После восстановления прямого доступа проверки продолжаются
  автоматически. По умолчанию используются HTTPS по IP Cloudflare и Google,
  чтобы отказ DNS через прокси не мешал проверке.
- Кандидат должен успешно передать данные два раза подряд; доступны четыре
  попытки. Между попытками есть пауза. Это помогает выявить узлы, которые сначала
  отвечают, а после установления соединения блокируются провайдером.
- Рабочий текущий сервер не заменяется более быстрым. Восстановившийся прежний
  сервер не становится предпочтительным автоматически.
- «Н/д» не удаляет сервер и не помещает его в вечный чёрный список. При следующем
  поиске или ручной проверке он проверяется снова.
- Если нет рабочего резерва, выбранный сервер сохраняется. Ошибка управляющего
  API не считается доказательством отказа конкретного сервера.
- Обычное переключение использует Clash API и не перезапускает Podkop.

Поиск большого пула длится дольше одного интервала; на это время параллельный
поиск кандидатов заменяет обычные проверки. 5 секунд — период в штатном режиме, а не жёсткая
гарантия времени восстановления. Старые соединения при переключении обрываются:
они не могут автоматически мигрировать между прокси.

Проверка WAN консервативна: если все прямые контрольные точки блокируются вашим
провайдером, переключение приостанавливается даже при доступности других сайтов.
В этом случае задайте доступные прямые HTTPS URL в настройках. Для обхода
используется подтверждённая метка Podkop `0x00200000`; при неизвестной схеме меток
автоматические изменения блокируются. Контрольные точки не дают абсолютного
доказательства доступности всего интернета.

Никакая конечная проверка не доказывает работоспособность всех сайтов, UDP или
всех объёмов трафика. Если провайдер блокирует соединение только после большого
объёма данных, настройте `qualify_url` под подходящий небольшой тестовый файл.
Лимит ответа — 64 КиБ. Частые проверки расходуют трафик.

## Подписки и протоколы

Встроенный импорт:

- JSON sing-box с `outbounds`, массив outbound или одиночный outbound;
- список URI, по одной ссылке на строку;
- base64/base64url обёртка списка URI.

URI-конвертер: VLESS, VMess, Trojan, Shadowsocks, Hysteria2 (`hy2`), TUIC,
SOCKS5 и HTTP. Поддерживается ограниченный, проверяемый набор параметров:
TLS/Reality, WebSocket, HTTP/2, gRPC, HTTPUpgrade и обычный TCP. Неизвестные
параметры отклоняются, а не молча теряются. VMess/TUIC и остальные протоколы
проверены тестовыми конфигурациями; реальные сетевые тесты проведены на VLESS.

**Для полного набора параметров установленного sing-box используйте native JSON.**
Объекты передаются в `sing-box check`; аддон не заявляет поддержку протокола,
который не поддерживается установленным ядром или его compile tags.
В этом выпуске импортируются самостоятельные proxy outbounds с `server` и
`server_port`. Detour-цепочки, endpoints, обращения к локальным файлам,
маршрутизация из подписки, Clash YAML, SSR и Xray JSON не поддерживаются.
sing-box сам по себе не является универсальным конвертером подписок.

Пулы нескольких подписок объединяются, одинаковые конфигурации дедуплицируются.
Неответившие серверы сохраняются. При ошибке загрузки или валидации рабочий пул
остаётся прежним. Исчезнувший из подписки активный узел удерживается до смены
выбора. Пул автоматически синхронизируется с подписками. Каждый источник имеет
свой последний проверенный кэш: отказ одного не мешает принять новые серверы
из другого. При полном отказе сохраняется последний рабочий пул.

## CLI и восстановление

```sh
podkop-autoswitch doctor       # зависимости, текущий sing-box check, API
podkop-autoswitch fetch        # загрузить и проверить, без применения
podkop-autoswitch plan         # подготовить и проверить интеграцию, без записи
podkop-autoswitch preflight    # настоящие проверки в отдельном ядре
podkop-autoswitch sync-pool    # загрузить подписки и автоматически синхронизировать пул
podkop-autoswitch apply        # служебная ручная команда, в обычной настройке не нужна
podkop-autoswitch status
podkop-autoswitch select pas_0123456789abcdef01234567-out
podkop-autoswitch detach       # восстановить исходный Podkop
logread -e podkop-autoswitch
```

Рабочие результаты: `/tmp/podkop-autoswitch`. Приватные подписки и исходная
конфигурация: `/etc/config/podkop-autoswitch` и `/etc/podkop-autoswitch`, права
0600/0700. Не публикуйте эти файлы и диагностические логи проверок sing-box.

Watchdog возвращает конфигурацию, если применение не подтверждено в течение
90 секунд после начала записи. Незавершённая транзакция также восстанавливается
при запуске службы. `detach` отказывается перетирать настройки, если после
подключения аддона Podkop был изменён вручную: сначала объедините изменения с
`/etc/podkop-autoswitch/original-podkop`.

Удаление:

```sh
curl -fLsS https://raw.githubusercontent.com/fackerghost/Podkop-AutoSwitch/main/uninstall.sh -o /tmp/pas-uninstall.sh && sh /tmp/pas-uninstall.sh
```

## Сборка и проверка

```sh
python3 tools/build_ipk.py
```

IPK не содержит машинного кода. Для APK используйте OpenWrt SDK соответствующего
выпуска: скопируйте `package/podkop-autoswitch` в SDK `package/` и выполните
`make package/podkop-autoswitch/compile V=s`. Workflow GitHub собирает APK
официальным SDK. Не переименовывайте IPK в APK.
